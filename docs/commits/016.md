# Overview del incremento 016 — Pedidos con pago de demostración

Fecha: 2026-11-05. Rama prevista: `feature-pedidos`. Mensaje propuesto: `feat: add orders with demo payment and stock deduction through movements`.
Estado: **en revisión** (código, pruebas y documentación listos; pendiente de tu revisión antes de confirmar, tarea C16-15). La API pasa de 34 a **38 operaciones**.

## Resultado

| Área             | Cambio                                                                                                                                                                                                                                      |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pedido           | `POST /orders` (solo `cliente`): líneas del menú (simples y combos), punto, piso, indicación y nota. El servidor calcula el total (máximo 200.000 COP, sin mínimo) y guarda una copia de nombres, precios y costos, del punto y de la zona. |
| Pago             | Tarjeta de demostración: `4242…4242` aprueba, `4000…0002` rechaza con `402` sin dejar rastro; cualquier otra → `400`. Solo se guardan los últimos cuatro dígitos.                                                                           |
| Saldo            | Al pagar, un movimiento `OUT` por producto simple (los combos descuentan sus componentes), con razón «Pedido #1001», el cliente como autor y `orderId`. Se bloquea en orden de id para evitar interbloqueos.                                |
| Movimientos      | `MovementsService` expone `lockProduct`, `applyLocked` y `applyMovement`; `create` conserva su contrato HTTP y el orden de errores. `GET /movements` suma `orderId`.                                                                        |
| Idempotencia     | Encabezado `Idempotency-Key` obligatorio y huella del contenido; la misma clave y contenido devuelve el pedido (`200`), otro contenido → `409`. Un candado por (cliente, clave) cubre las peticiones simultáneas.                           |
| Lectura          | `GET /orders` y `GET /orders/:id`: el cliente solo ve los suyos (el ajeno es `404`); admin y operador ven todos con nombre y teléfono del cliente. Sin costos. `repartidor` → `403`.                                                        |
| Cancelación      | El cliente cancela solo en `recibido`; admin y operador hasta `en_preparacion`, con motivo. Devuelve el saldo con movimientos `IN` (aunque el producto se haya desactivado) y reembolsa el pago de demostración.                            |
| Historial        | Tabla `order_events` con la hora de cada estado; base del seguimiento.                                                                                                                                                                      |
| Usuarios         | Un cliente con pedidos no se puede eliminar (`409`).                                                                                                                                                                                        |
| Migración        | `1791244807000-orders`: tablas `orders`, `order_items`, `order_item_components`, `order_events`, número desde 1001 y `stock_movements.order_id`. `down()` aborta si existe algún pedido.                                                    |
| Fuera de alcance | Estados `en_preparacion` a `entregado` (017 y 018), hora estimada, teléfono del repartidor y WhatsApp (018), pago real, propinas y cupones.                                                                                                 |

## Qué debes hacer tú

1. Con Docker Postgres arriba: `npm run migration:run` (el seed no cambia).
2. Prueba el flujo: registra un cliente (`POST /customers`), inicia sesión con su correo y llama a `POST /orders` con `Idempotency-Key` y la tarjeta `4242424242424242`; luego cancélalo y mira `GET /movements`.
3. Revisa y, si estás de acuerdo, pídeme el commit (rama `feature-pedidos`).
